## 📖 1. 產品願景與高校吉他社痛點

在各大專院校吉他社（如期初迎新野餐、新生盃、三家練團配對、期末成果發表會），幹部常需要在短時間內將 20 到 100+ 位社員迅速分組編成表演樂團。傳統人工紙筆排組或隨機抽籤常導致以下嚴重痛點：

1. **音樂喜好斷裂**：想玩日系動漫搖滾（如 Yorushika、結束バンド）的社員與只想彈唱中文抒情慢歌（如周杰倫、告五人）的社員被硬分在一組，選歌會議陷入僵局。
2. **關鍵角色集中或落空**：少數會木箱鼓或主唱的社員集中在同一組，造成其他組完全沒有節奏或主唱，無法成團。
3. **多工全能人才被浪費**：同時精通木吉他、主唱、木箱鼓的「大腿」被湊在一起，反而其他組缺件嚴重。
4. **現場等待冗長尷尬**：過去使用 Google 表單或紙本統計，幹部在台下開 Excel 抓破頭算半小時，全場新生在台下尷尬滑手機。

**Guitar Group** 提供類似 **Kahoot** 的極速即時互動體驗：
- **活動負責人（房主）**：筆電接大螢幕投影 4 碼房間代號與 QR Code，即時看見動態進房氣泡與樂器統計。
- **社員（參與者）**：手機掃碼，免註冊登入，30 秒內選好樂器技能（木吉他、電吉他、木箱鼓、主唱...）與音樂喜好。
- **一鍵智慧分組**：房主按下「開始分組」，Cloudflare 邊緣節點即刻啟動模擬退火演算法，數十毫秒內完成多目標全局最佳化。
- **全場同時開獎**：每位社員手機立即顯示「你在 第 X 組！」以及同組隊友的**完整技能**、**音樂偏好**與**本組推薦公約數曲風**，現場直接圍成一圈敲定練團歌單！

## 🏛️ 2. 全端 Cloudflare 原生架構

系統採純 Cloudflare 原生無伺服器架構，**無外部資料庫、無 Redis、零冷啟動**：

```
                    ┌────────────────────────────────────────┐
                    │               Client                   │
                    │   (Vite + React 19 + Tailwind CSS)     │
                    └──────────────────┬─────────────────────┘
                                       │ HTTP / WebSocket
                                       ▼
┌────────────────────────────────────────────────────────────────────────────┐
│                        Cloudflare Worker (Gateway)                         │
│  - 路由分發 / 靜態 SPA 資源服務 (Cloudflare Assets)                          │
│  - 房間路由轉發至對應 Durable Object (idFromName(roomCode))                 │
└──────────────────────────────────────┬─────────────────────────────────────┘
                                       │ env.ROOM_DO.get(id)
                                       ▼
┌────────────────────────────────────────────────────────────────────────────┐
│                       RoomDO (Durable Object)                              │
│  - 單房狀態中心 (Linearizable In-Memory State)                               │
│  - WebSocket Hibernation API 即時雙向廣播 (高併發低記憶體)                  │
│  - 房主權限控制 (Host Secret Token 驗證)                                    │
│  - 內建分組最佳化引擎 (Grouping Optimization Engine, Pure TypeScript)        │
│  - 自動生命週期與清理 (Alarm TTL: 24 小時無操作自動釋放記憶體與儲存)          │
└────────────────────────────────────────────────────────────────────────────┘
```

### 架構特色
- **WebSocket Hibernation API**：手機客戶端在房間等待時連線處於休眠狀態，不計入 Worker CPU 時間；房主開獎或新成員加入時瞬間喚醒廣播。
- **單房線性一致（Linearizable State）**：每個 4 碼房間對應專屬 `RoomDO` 實例，所有進房、設定變更循序寫入，絕無 Race Condition。
- **24 小時自動 TTL 清理**：活動結束後 24 小時內若無任何操作，Durable Object 自動觸發 Alarm 清空 Storage 與狀態，不佔用任何長久儲存費用。
- **HTTP Polling 自動備援**：若校園 Wi-Fi 或行動網路代理封鎖 WebSocket，前端自動平滑回退為 REST 輪詢，連線不中斷。

## 🧮 3. 多目標分組最佳化演算法核心數學模型

分組問題屬於 NP-hard 的組合最佳化問題。系統採用**啟發式稀缺錨定（Constructive Anchor Seeding）**結合**模擬退火（Simulated Annealing）**，尋求全局適應度 $F(P)$ 最大化：

$$F(P) = w_{\text{role}} \cdot S_{\text{role}}(P) + w_{\text{music}} \cdot S_{\text{music}}(P) + w_{\text{div}} \cdot S_{\text{div}}(P) - \text{Penalties}(P)$$

### 3.1 稀缺角色加權與分散因數 ($W_r$)
設角色 $r$（如木箱鼓、爵士鼓、主唱）在全場 $N$ 名社員中僅有 $C_r$ 位具備，目標劃分為 $K$ 組：

$$W_r = 1.0 + \max\left(0, \frac{K - C_r}{K}\right) \times 2.0$$

當全場木箱鼓人數少於總組數（$C_r < K$）時，$W_r$ 權重大幅飆升（最高達 3.0），驅使演算法將稀缺鼓手分散到不同組，避免單一組雙鼓、其他組缺鼓的悲劇。

### 3.2 邊際效益遞減函數 ($\text{Gain}$)
吉他社常出現一堆人只會木吉他的情況。為防止同組堆積過多相同樂器，組內第 $k$ 位具備角色 $r$ 的社員所帶來的邊際效益為：

$$\text{Gain}(k) = \frac{W_r}{1 + 0.8 \times (k - 1)}$$

- 第 1 位吉他手：貢獻 $100\%$ 的 $W_r$ 效益。
- 第 2 位吉他手：貢獻降低至 $55.6\%$。
- 第 3 位吉他手：貢獻降至 $38.5\%$。
演算法因此會自發將吉他手與其他角色進行最佳配比。

### 3.3 全能多工人才浪費懲罰 ($P_{\text{waste}}$)
在吉他社中，一人身兼「木吉他 + 主唱 + 木箱鼓」的多工好手是組團核心救火隊。若多位全能樂手被分配在同一組，而其他組欠缺節奏或主唱，系統會對該組施加超額多工浪費懲罰：

$$P_{\text{waste}} = \sum_{G \in P} 30.0 \times \max(0, \text{VersatileCount}(G) - 1)$$

### 3.4 最差組相容度保護 (Min-Max Fairness Safeguard)
許多貪婪演算法為了衝高平均分數，會犧牲最後一組變成「雜牌孤兒團」。Guitar Group 引入最差組保護機制：

$$S_{\text{music}}(P) = 0.7 \times \text{AvgMusic}(P) + 0.3 \times \min_{G \in P} \text{Music}(G)$$

確保沒有任何一組被系統拋棄，組與組之間的體驗差距降至最低。

### 3.5 階層式音樂偏好匹配與父層向上溯源 (Hierarchical Fallback)
系統內建臺灣與華語高校吉他社**完全真實、無虛構**的音樂風格與代表歌手庫（包括但不限於：周杰倫、告五人、理想混蛋、茄子蛋、草東沒有派對、Taylor Swift、keshi、Yorushika、YOASOBI、白小白、LB利比、隊長、承桓等）。

若社員 $A$ 選了 `Justin Bieber`，社員 $B$ 選了 `keshi`，兩者細項藝人雖然不完全相同，但系統能自動向上溯源至共同父層大類 `western_pop_rnb`（西洋流行 / R&B），賦予 $0.6$ 的相容度得分：

```
                    [western_pop_rnb] (父層大類)
                     /             \
                    / (權重 0.6)    \ (權重 0.6)
                   ▼                 ▼
          [justin_bieber]         [keshi]
```
- **精確細項匹配（Exact Match）**：權重 $1.0$。
- **共同父層匹配（Parent Fallback）**：權重 $0.6$。
- **跨類相近風格（Genre Neighborhood）**：如獨立搖滾與西洋搖滾具備關聯，權重 $0.25$。
- **全團公約數加分（Consensus Core Bonus）**：組內若全員共同涵蓋某一曲風領域，額外加分獎勵。

## 📊 4. 實機模擬評測 (Simulation Benchmark)

本系統內建大規模模擬套件，於 10 到 300 名社員（微型成果展到大型全校音樂祭）進行對比評測。以下為實機基準數據（與隨機抽籤 Random 及單純貪婪 Naive Greedy 對比）：

| 測試規模 (人數) | 分配組數 | Guitar Group 最佳化引擎 | 隨機分組 (Random) | 樸素貪婪 (Naive Greedy) | 最佳化勝出幅度 | 運算時間 (V8) |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **10 人** | 2 組 | **48.2** | 47.3 | 41.5 | +0.9 | 19.3 ms |
| **20 人** | 5 組 | **53.9** | 38.1 | 46.2 | +15.8 | 34.1 ms |
| **30 人** | 7 組 | **61.4** | 45.0 | 55.1 | +16.4 | 25.8 ms |
| **50 人** | 12 組 | **66.2** | 43.0 | 64.3 | +23.2 | 30.6 ms |
| **100 人** | 25 組 | **56.9** | 41.8 | 55.4 | +15.1 | 30.1 ms |
| **300 人** | 75 組 | **51.9** | 40.3 | 57.0* | +11.6 | 70.6 ms |

> 註：在 100~300 人規模下，樸素貪婪演算法（Naive Greedy）雖然靠塞滿前幾組衝高整體均分，但其**最差組得分崩跌至 22.8 分**（出現嚴重的被遺棄組）；而 Guitar Group 憑藉 Min-Max 最差組保護機制，最差組分數依然維持在 **51.3 ~ 43.9 分**（提升超過 +88%），大幅保障每位社員的參與體驗！

## 🛠️ 6. 本地開發指南

### 環境要求
- Node.js 20+
- pnpm 9+

### 安裝依賴
```bash
pnpm install
```

### 啟動本機開發伺服器
```bash
pnpm dev
```
啟動後開啟瀏覽器訪問 `http://localhost:5173`。

### 執行完整測試套件
```bash
# 執行全部單元測試、演算法測試與 UI 測試
pnpm test --run

# 進行靜態 TypeScript 型別檢查
pnpm run typecheck
```

### 生產環境靜態編譯
```bash
pnpm run build
```
編譯產物將輸出至 `./dist` 目錄。

## 🚀 7. Cloudflare 正式發布指南

系統由 Cloudflare Workers + Durable Objects (`RoomDO`) + Cloudflare Assets 一體成型驅動。

### 7.1 驗證部署打包（Dry Run）
在正式部署前可透過 dry run 檢查配置與綁定：
```bash
npx wrangler deploy --dry-run
```

### 7.2 一鍵發布至生產環境
```bash
npx wrangler deploy
```
Wrangler 將會自動：
1. 編譯並打包 `workers/app.ts` 與 `workers/room-do.ts`。
2. 上傳 `./dist` 前端 SPA 靜態資源至 Cloudflare Assets。
3. 建立或更新 `ROOM_DO` Durable Object 綁定與遷移。
4. 部署至正式網域：
   - `guitar-grouper.jjmowlab.com`
   - `guitar-group.jjmowlab.com`
